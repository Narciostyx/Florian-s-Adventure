| 项 | 值 |

> 实测与踩坑：[构建记录](../build/m21-ai.md)

## 1. 目的

提供敌人与 NPC 的决策与移动：感知、行为选择、寻路、攻击执行。AI 只输出意图，实际移动与伤害仍由物理/战斗模块执行。

## 2. 范围

**负责**

- 感知：视野半径、视线遮挡、听觉（事件驱动）、仇恨列表。
- 行为：idle、巡逻、追击、攻击、逃跑、返回出生点。
- 行为选择：轻量状态机 + 条件表（数据驱动）；可选行为树。
- 寻路：A* 网格寻路（基于 M12 可行走格），路径平滑与重算节流。
- 移动执行：朝目标点移动，调用 M13 `move`。
- 攻击执行：进入范围后调用 M20 `spawnAttack`，遵守冷却。
- 敌人生成：出生点、波次、刷新规则（由 M25 调度）。
- NPC 日程（可选）：按时间段移动到目标点。

**不负责**

- 伤害计算（M20）。
- 动画播放（M10，AI 只设置参数）。
- 对话/任务（M23）。
- 群体编队/复杂战术（非目标）。

## 3. 核心概念与数据结构

```cpp
enum class AiState { Idle, Patrol, Chase, Attack, Flee, Return };

struct Perception {
    float sightRadius = 120.0f;
    float attackRange = 20.0f;
    scene::EntityId target;
    float lastSeenTime = 0.0f;
};

struct AiAgent {
    AiState state = AiState::Idle;
    glm::vec2 home;
    float stateTime = 0.0f;
    float attackCooldown = 0.0f;
    std::vector<glm::ivec2> path;
    int pathIndex = 0;
};
```

- 感知每 N 个固定步执行一次（默认 6 步），降低开销。
- 路径重算节流：目标移动超过 1 格或路径耗尽时重算。
- AI 决策失败时回退到 idle，不阻塞其他系统。

## 4. 公共接口

实际落地是具体类 `fa::ai::AiService`（没有引入 `IAiService` 接口）：

```cpp
namespace fa::ai {

class AiService {
public:
    AiService(const tilemap::Tilemap& map, physics::PhysicsWorld& physics,
              combat::ICombatService* combat = nullptr);
    void update(scene::World& world, float deltaSeconds);
    void setAggro(scene::World& world, scene::EntityId agent, scene::EntityId target);

    bool findPath(tilemap::TileCoord from, tilemap::TileCoord to,
                  std::vector<tilemap::TileCoord>& out) const;
    static bool hasLineOfSight(const tilemap::Tilemap& map,
                               tilemap::TileCoord from, tilemap::TileCoord to) noexcept;

    AiStats stats() const noexcept;
    std::size_t pathNodeCount(scene::EntityId agent) const noexcept;
    void clearPaths() noexcept;   // 读档后丢弃缓存路径，保留 agent 组件状态
    void clear() noexcept;
};

struct AiAgentSnapshot {
    AiState state;
    core::Vec2 home;
    float stateTime, attackCooldown, loseTimer, repathTimer;
    bool targetVisible;
};
AiAgentSnapshot captureAiAgent(const AiAgent&) noexcept;
void applyAiAgentSnapshot(AiAgent&, const AiAgentSnapshot&) noexcept;

} // namespace fa::ai
```

草案里的 `IAiService` 没有再引入：目前只有一个实现。目标用 `AiTargetTag`
标记，而不是依赖 M16 的 `PlayerTag`；这样玩家、假人和 NPC 都可以被感知。

## 5. 依赖关系

- 设计上依赖 M11（ECS）、M12（寻路网格）、M13（移动/视线）、M15（敌人定义）、M20（攻击执行）。
- **实际落地**：`fa_ai` 链接 `fa_core`、`fa_scene`、`fa_physics`、`fa_tilemap`、
  `fa_combat`、`fa_player`。它读共享的 `player::Health` 组件（M20 也写这个组件），
  但不 include M16 的 `PlayerController`。
- 不依赖 M16；玩家只是一个带 `AiTargetTag` 的目标，标签由组装根添加。
- 不依赖 M23；NPC 对话由 M23 在交互时触发，AI 只负责靠近。

## 6. 扩展点

- 新增行为：注册 `IAiBehavior`，按 `EnemyDef` 选择。
- 新增感知方式（嗅觉、区域触发）。
- 新增寻路代价（道路更优、避开灯光）。
- 群体行为（包围、召唤）作为高层协调器。

### 可配置参数（ADR-0002 决策 1）

- 敌人数值（生命、速度、攻击力、耐力相关）全部走内容库，不在代码中硬编码。
- 追击/攻击节奏以 `BehaviorProfile` 描述，可被 JSON 覆盖。
- 敌人同样遵守闪避与硬直接口；但 v1 敌人不使用闪避，仅保留字段。
- 战斗调试面板（M27）可运行时修改这些参数。

## 7. 实现落地

P1，Phase D，已完成：

- 感知：`AiTargetTag` + 视线 + 视野半径，默认每 6 个固定步扫一次。
- A*：4 邻接、Manhattan 启发、4096 节点上限、视线平滑；不可达返回 false。
- 状态机：Idle/Patrol/Chase/Attack/Flee/Return；攻击冷却与范围判定。
- 移动走 M13 `PhysicsWorld::move`，攻击走 M20 `ICombatService::spawnAttack`。
- `AiAgent` 是纯数据，路径由 `AiService` 私有保存；没有把 `std::vector` 放进 ECS。
- app：独立 agent + 静止假人验证追击/攻击，摘要 `m21:` 行与 smoke OK 的 `+M21`。

验收：A* 绕墙；丢失目标后返回；攻击有冷却且不重叠；低血量逃跑；无目标巡逻。

## 8. 风险与开放问题

- A* 在大量敌人时开销高；需限制同时寻路数量与路径长度。
- 敌人卡在角落需要“脱困”逻辑（随机微移/传送回出生点）。
- 行为数据驱动的表达能力与调试成本需平衡；v1 用代码状态机更简单。
- 是否需要 NPC 日程系统？影响 M23 与 M22 的耦合方式。
