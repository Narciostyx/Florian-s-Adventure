# 美术资源策略：色块占位优先

本文定义 v1 期间「资源长什么样」的规则。它是 [M05 Asset Pipeline](../modules/05-asset-pipeline.md) 与 [M06 Rendering](../modules/06-rendering.md) 共同依赖的约束。

## 1. 决定

**在全部玩法模块完成之前，仓库里不放任何图片文件。** 每一张纹理都由 [catalog](../modules/05-asset-pipeline.md#assetentry-与-assetcatalog) 里的颜色声明**程序化生成**。

理由：

- 美术资源会拖慢模块进度，而且在玩法尚未定型时画出来的东西几乎必然要重画。
- 「缺图就跑不起来」会让每个模块的验收都依赖外部文件，冒烟、CI、全新克隆都变脆。
- 色块能验证**几何**（尺寸、锚点、瓦片对齐、碰撞盒），而这正是前几个阶段真正要确认的东西。

这不是临时凑合，而是 v1 期间**唯一的资源形态**；真实美术是后置的独立步骤（见 §5）。

## 2. 占位规格

一张占位纹理由三个字段决定，全部写在 catalog 里：

| 字段 | 含义 |
|---|---|
| `size: [w, h]` | 占位图像的像素尺寸，必须与将来真实贴图一致 |
| `color` | 主色，`#rrggbb` 或 `#rrggbbaa` |
| `altColor` | 可选第二色；省略时等于 `color` |
| `tile` | 可选棋盘格边长；省略或 `<= 0` 表示纯色块 |

生成规则：

```text
tile <= 0         → 纯色块（color）
tile >  0         → 以 tile 为边长的双色棋盘（color / altColor）
```

| 写法 | 视觉 | 用在哪 |
|---|---|---|
| 纯色块 | 一整块颜色 | 剪影类物件：角色、标记、道具 |
| 棋盘 | 两色交错方格 | 平面类图块：地面、墙、水面 |

棋盘的意义不只是好看：**相邻同色纯色块会糊成一片**，分不清哪块是哪个瓦片、
也看不出是否对齐。地面与墙体一律用棋盘。

## 3. 颜色约定

| 用途 | 约定 | 示例 |
|---|---|---|
| 已实现、行为正确 | 语义色（草绿、土棕、肤色） | `#4a8250` 草地、`#6b4a2f` 耕地 |
| 尚未接入的占位 | **洋红 `#ff00ff`** | catalog 默认值就是洋红，忘填 `color` 会一眼看出来 |
| 调试图元（碰撞盒、锚点） | 半透明纯色 | 由 M06 的 `drawDebugRect` 画，不进 catalog |

洋红是刻意的：它是像素画里最少自然出现的颜色，出现在画面上就是「这里还缺东西」。

## 4. 尺寸必须与将来的真实贴图一致

`size` **不是**随便填的。它决定：

- 精灵在屏幕上的物理尺寸（配合 [像素度量](pixel-metrics.md)）；
- 碰撞盒与锚点的相对位置；
- M06 的整数缩放是否会把精灵切成半像素。

因此改 `size` 等于改玩法手感，必须同时检查 [ADR-0003](../adr/0003-tile-and-collision-metrics.md) 的瓦片与碰撞盒基准。
角色占位当前是 16×24，而脚部碰撞盒是 10×6——**这两个数字都要在接入真实美术时保持不变**，
否则所有已经调好的移动与碰撞都要重调。

## 5. 真实美术怎么接进来

真实图片到位时**不改代码**，只改 catalog：

```json
{ "id": "tex.ground.grass", "kind": "texture", "path": "tiles/grass.png",
  "size": [16, 16], "tile": 8, "color": "#4a8250", "altColor": "#5c8a42" }
```

规则：

1. 加上 `path` 后，`color` / `altColor` / `tile` **保留**——它们是「文件读不到时的兜底」，
   删掉等于放弃降级能力。
2. 注册一个 `IImageDecoder`（PNG 用 stb_image 或 SDL_image，届时再定）。
3. `size` 必须与图片实际尺寸一致；不一致时以图片为准，但要在同一批改动里同步 catalog 与玩法数值。

因为解码器是注入的，**M05 与 M06 都不需要改**；这也是当初拒绝「M05 直接调 SDK 解码」的原因。

## 6. 当前 catalog 清单

`src/app/main.cpp` 的 `kCatalogText` 里的四条，全部 path-less：

| id | 尺寸 | 形态 | 用途 |
|---|---|---|---|
| `tex.ground.grass` | 16×16 | 棋盘（tile 8） | 草地瓦片 |
| `tex.ground.soil` | 16×16 | 棋盘（tile 4） | 耕地瓦片 |
| `tex.actor.player` | 16×24 | 纯色块 | 玩家 |
| `tex.marker` | 8×8 | 纯色块（白） | 鼠标位置标记 / 调试图元底色 |

新增资源时按 [模块文档](../modules/05-asset-pipeline.md) 的校验规则填写：
`id` 唯一、`kind` 合法、path-less 纹理必须给 `size`、颜色必须是合法 HEX。

## 7. 不做的事

| 不做 | 原因 |
|---|---|
| 提交 `.png` / `.aseprite` 到仓库 | v1 期间不存在真实美术；等到有美术时再一并定目录与 LFS 策略 |
| 用字体图标 / emoji 当占位 | 渲染器不画文字（文字归 M09），色块是唯一能画的形态 |
| 程序化生成「像样的」贴图（噪声草地等） | 会掩盖对齐问题；色块最容易暴露尺寸与排序错误 |
| 占位尺寸随窗口/缩放变化 | 尺寸是玩法参数，不是显示参数 |
