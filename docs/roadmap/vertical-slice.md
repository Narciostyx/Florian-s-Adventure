# 首个垂直切片

垂直切片的目标不是“做完一个系统”，而是用最小内容验证**完整玩家体验**：一天之内，玩家能种地、能战斗、能存档。

> **当前状态（玩法验证第十一增量，2026-10-22 实测）**：28 个模块全部实现；
> `fa_tests.exe` 554 用例 / 30416 断言全绿，Debug / Development / Release × x64
> 零 warning，`--frames 60` 与 `--play-test` 三配置 exit 0。
>
> **本轮更新**：地图布局外置到 `data/maps/*.json`（`farm.json` / `farm-scripted.json` /
> `forest.json`），`--play` 通过 `SceneStack::replace` 在两张独立 40×23 地图之间切换；
> `docs/code-reference.md` 补全链接依赖图、运行时接线、全局类关系以及 28 个模块的
> 类职责/方法职责。
>
> 可手动游玩（`--window --play`）：启动进入**主菜单**（新游戏/继续/存档槽/退出），
> `Esc` 打开暂停面板（继续/保存/存档槽/主菜单）。`WASD` 移动，快捷栏 1–3 是
> 锄头/浇水壶/种子，左键使用并自动收获成熟作物；右键近战，敌人死亡掉落并自动拾取；
> 床边 `E` 睡觉；橙色**出货箱**旁 `E` 把所有作物送进出货箱，次日结算金币；
> 紫色**商人**旁 `E` 打开商店，可买种子、卖萝卜；`I` 打开**背包面板**，
> 点击 MOVE 在背包与快捷栏之间移动 1 个物品；HUD 现在同时显示生命与耐力。
>
> 内容/商店/叙事/资源目录已移到 `data/*.json`，地图布局在 `data/maps/*.json`
> （`farm.json` / `farm-scripted.json` / `forest.json`），play 实体由
> `data/entities.json` 生成；窗口/UI 缩放/玩法参数在 `config/game.json`，缺失时回落默认值。
> 纹理优先读 `assets/*.png`（stb_image），缺图/解码失败回落到程序占位。
> 主菜单等面板居中，字号由 `ui.scale`（默认 1.25×）放大；窗口最小 1280×720、可放大。
>
> HUD 已去掉多余的 `PAUSE` 按钮（`Esc` 仍暂停），日期/时间/季节/区域移入左侧
> HUD 下方。新增湿土、萝卜 4 阶段（种子/幼苗/成苗/成熟）、箱子、史莱姆贴图；
> 作物阶段由 `data/content.json` 的 `seed_sprite`/`stage_sprites` 决定，
> 5 天成熟与 3 个 `stage_days` 不变。
>
> 地图在 play 模式拆成两张独立的 **40×23** 地图：农场与林地。门口 `portalAt`
> 命中后由 `SceneStack::replace` 真正替换场景，农田/背包/叙事/玩家生命耐力放在
> 组装根的 `GameState` 中，因此过图不会丢状态；HUD 显示 `FARM`/`FOREST`。
> 林地有额外的 dummy 敌人与**荆棘**（3 格）：站在荆棘上每 0.7s 扣 5 点生命，
> 生命归零会晕倒、切回农场床边复活，并扣除 10% 金币。地上的掉落物与当前地图
> 随存档写入并读回。scripted smoke 仍使用 40×23 农场图。
>
> 睡眠规则：任意时间可睡，醒来固定为次日 08:00。睡满 8 小时恢复全部体力；
> 不足 8 小时按 `(实际小时 / 8)²` 递减，最低保留 1%。
>
> 已持久化并读回：日期/时间/天气、当前地图、玩家位置/朝向/耐力、背包/快捷栏/装备、
> 农田与作物状态、金币、出货箱待结算清单、加工任务与每日商店余量。
> `--play-test` 无头串起种植 → 5 天 → 收获 → 补种 → 战斗/掉落 →
> 睡眠（8h/7h/1h 恢复档位）→ 商店买卖 → 出货结算 → 保存 → 主菜单 → 读档 →
> 暂停/存档槽，逐项校验后返回失败码。
>
> 仍缺：**play 模式尚未接 NPC 对话/任务**（M23 只在脚本演示与单元测试里跑通）、
> 死亡菜单/读档选项、叙事/AI/世界对象存档、商店季节库存与加工 UI；
> 背包面板一页只列 8 个堆叠；音频仍是占位音，没有真实音效/音乐；
> 1920×1080、60 FPS 与 30 分钟稳定性尚未验证。
>
> 当前实际内容为 **6 物品 / 1 作物 / 1 配方 / 1 敌人 / 2 掉落表**；
> 原定的 3 作物、2 敌人、12 物品、8 音效与 1 首音乐尚未补齐。

### 立即运行

```powershell
# 可操作种植会话（需要窗口）
.\build\bin\x64\Debug\fa_app.exe --window --play

# 无头自检：种植 + 5 天生长 + 收获 + 补种 + 战斗/掉落 + 睡眠档位 + 存档/菜单往返
.\build\bin\x64\Debug\fa_app.exe --play-test
```

操作：主菜单点「新游戏/继续/存档槽」；`WASD` 移动，`1–9` 选快捷栏，滚轮循环，
左键使用当前工具/种子，右键攻击，床边 `E` 睡觉，橙色出货箱 `E` 出货，
紫色商人 `E` 开商店，`I` 开背包，`Esc` 关闭面板/暂停，F3 统计，反引号控制台；
林地西侧的棕色**荆棘**会持续扣血，生命归零会在床边复活并损失 10% 金币；
控制台内 `time.addDays N` / `time.set HH:MM` 推进时间。
数据/配置/图片分别在 `data/`、`config/`、`assets/`；删除任意文件都会回落到内置默认值。

## 1. 切片目标

玩家在一个小型农场与相邻林地中：

1. 从主菜单开始，查看 HUD（日期、时间、金钱、生命、耐力）——**已完成**：
   主菜单/存档槽已接，HUD 同时显示生命/耐力/日期/时间/区域。
2. 用锄头开垦 3 块地，播下萝卜种子，浇水——**已可手动完成**（快捷栏 1–3 + 左键）；
   浇水后显示湿土贴图，萝卜按种子/幼苗/成苗/成熟 4 张阶段贴图显示。
3. 前往林地，用剑击败 2 只史莱姆，拾取掉落物——**已可手动完成**：穿过农场东侧门，
   `SceneStack::replace` 把场景换成独立的林地地图，林地里有两个 dummy；掉落拾取复用 M20。
4. 返回农场，收获已成熟作物（可通过调试命令推进时间）——**已可手动完成**；`time.addDays` 已提供。
5. 在出货箱卖出作物，获得金钱——**已可手动完成**：橙色出货箱旁 `E` 把作物加入待结算
   清单，次日结算到金币；紫色商人 `E` 可当场买卖（买种子、卖萝卜）。
6. 回家睡觉，触发日终结算与自动存档——**已可手动完成**：任意时间在床边按 `E`，
   醒来固定次日 08:00；睡满 8 小时回满体力，不足按 `(小时/8)²` 衰减、最低 1%。
   随后 `GameFlow::endDay()` → M22 推进 → M19 生长 → M24/M23 结算 → 自动存档。
7. 退出并重新启动，读档回到次日早晨——**已可手动完成**：主菜单「继续」加载 autosave
   （或在存档槽面板选择槽位）；位置、朝向、耐力、背包/快捷栏/装备、农田、
   日期/时间/天气与金币/出货清单/加工任务都写回并应用。

## 2. 范围与实际落地

### 2.1 原定切片范围（验收基线）

> 以下是原定基线；“不包含”里有些能力后来已在引擎层实现（季节、任务、加工），
> 但 play 可达性不同，以 2.2 为准。

**原定包含**

- 一张农场地图（约 40×30 瓦片）+ 一张林地地图（约 40×30）。
- 3 种作物：萝卜（4 天）、土豆（6 天）、草莓（8 天，再生）。
- 1 种工具：锄头；1 种武器：木剑；1 个浇水壶。
- 2 种敌人：史莱姆（近战）、蝙蝠（飞行/冲刺）。
- 1 个 NPC：商人（对话 + 商店）。
- 基础 HUD、背包、快捷栏、暂停菜单、主菜单。
- 日/夜循环、晴天/雨天。
- 单槽存档 + 自动存档。
- 基础音效与一首背景音乐。

**原定不包含**

- 季节系统（切片固定为春季）。
- 任务系统、好感度、节日。
- 加工、酿造、动物、钓鱼。
- 多地图大地图、传送网络。
- 手柄支持（架构预留，切片可不验证）。
- 编辑器（用 JSON 手工编辑地图）。

1920×1080/60 FPS/30 分钟稳定性。

> 最后做内容量与工程收尾。每项仍按“设计 → 实现 → 测试 → app 集成 →
> 三配置验证 → 回写文档”推进。

| 优先级 | 增量 | 目标 | 验收 |
|---|---|---|---|

| P0-2 | 死亡菜单与读档 | 生命归零进入 GameOver 面板（复活 / 读档 / 主菜单），金币惩罚只结算一次 | `--play-test` 校验面板、复活、读档、主菜单；三配置通过 |

| P2-1 | 内容补齐 | 土豆/草莓、蝙蝠、12 物品、8 音效、1 首音乐、真实像素美术 | 内容清单达到原定数量；audio 不再是占位音 |
| P2-2 | 工程收尾 | 全新克隆 CI、60 FPS/内存基线、1920×1080 像素检查、存档迁移链 | 新克隆一次通过；30 分钟 soak 无增长 |

**建议先做 P0-1（叙事接入 play）**，理由：

- M23 的服务、数据、测试和对话框绘制都已经存在，缺的只是 app 的交互分支与
  输入上下文；这是“投入最小、玩家可见收益最大”的一项。
- 它同时为 P0-3 的叙事存档和 P1-2 的任务日志铺路，避免先做 UI 再返工数据。
- 与 P0-2 共享“按 `AppState` 管理输入/暂停”的整理，可以在同一轮先把
  `Playing / Dialogue / Paused / GameOver` 的输入互斥定清楚。

**P0-1 第一步动作**：

1. 在 `processPlayerActions()` 的 `Interact` 分支识别 NPC（payload 23），调用
   `NarrativeService::startDialogue()` 并 `GameFlow::enterDialogue()`。
2. 在 `onEvents` 中把 Digit1–3 / Enter 路由给 `choose()` / `advance()`；
   对话结束后 `exitDialogue()`。
3. 复用 `buildHud()` 里已有的底部对话框；补任务状态显示。
4. 扩展 `--play-test`：对话 → 接任务 → 收集 → 完成 → 奖励入包。
5. 三配置验证后回写 M23/plan-status/本文件。

## 8. 开放问题

- 切片是否需要战斗？**已决定：保留**，M20/M21 已实现并跑通；但敌人反击与
  命中反馈仍未做。

- 死亡菜单的行为：默认复活、允许读档、还是回主菜单？金币惩罚在“读档”路径上
  是否回滚？需要产品确认。
- 叙事存档粒度：只存好感/任务/flags，还是连对话节点历史一起存？影响 M14 格式。
- 内容优先级：先补 3 作物/2 敌人/真实音频，还是先把现有 1 作物打磨到“手感完整”？
- 加工/任务 UI 是否属于 v1 切片，还是切片后再做？目前服务已实现但没有 play 入口。
- 音效/音乐素材来源（自制/购买/免费）仍未定；当前是代码生成的占位 PCM。
- 性能目标硬件与分辨率（1280×720 / 1920×1080 / 60 FPS）尚未形成基准。
