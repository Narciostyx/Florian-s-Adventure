# ADR-0003：瓦片尺寸与碰撞盒基准

- 状态：Accepted
- 日期：2026-10-17
- 决策者：项目所有人（代行决策：架构负责人）
- 相关模块：M06、M09、M10、M12、M13、M16、M17、M19
- 取代：无

## 背景

`docs/architecture/pixel-metrics.md` 列出了 16×16 与 32×32 两种瓦片方案及三种碰撞盒方案。该决定是所有美术资源、地图、相机、碰撞与动画的共同基准，必须在开始写 M00/M06 前固定。

决策驱动力：

- 单人开发，美术资源需要自己产出，成本敏感。
- 农场经营需要较宽视野（看到整块田地）。
- 战斗需要角色动作可读（但可通过特效/顿帧/音效补偿）。
- 目标只有 Windows，适配 1080p/1440p 即可。

## 决策

采纳**方案 A**，参数如下：

| 项 | 值 |
|---|---|
| 瓦片尺寸 | 16 × 16 px |
| 虚拟分辨率 | 640 × 360（40 × 22.5 瓦片可视） |
| 窗口缩放 | 默认整数缩放 + letterbox，不插值；`window.fill` 可启用精确比例填满（nearest） |
| 角色帧尺寸 | 16 × 24 px |
| 角色朝向 | 4 向（down / up / left / right），斜向复用左右 |
| 精灵对齐点 | 脚底中心（feet anchor） |
| 碰撞盒 | 脚部盒 10 × 6 px，水平居中，盒顶距脚底 6 px |
| 排序键 | `(layer, sortY, entityId)`，`sortY = feetWorldY` |
| 交互目标 | 朝向前方 1 格（16 px） |
| 移动速度 | 走 90 px/s，跑 150 px/s |
| 闪避位移 | 48 px / 0.25 s（均速 192 px/s，ease-out） |
| 近战判定范围 | 24 × 20 px（以脚底中心前方偏移 12 px 为基准） |
| 相机 | 不提供自由缩放；窗口适配由 `Viewport` 负责（默认整数倍，可选 fill） |

### 明确不做

- 不做 32×32 瓦片，不做混合尺寸（世界 16 / 角色 32）。
- 不做全身碰撞盒与圆形碰撞盒。
- v1 不做角色换装分层；仅预留 `SpriteAttachment` 偏移字段（武器/工具挂点）。
- v1 不做相机自由缩放（避免像素缩放与过滤混用导致的模糊/波浪纹）。

## 考虑过的其他方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 16×16 + 640×360 + 脚部盒 | 美术量最低、视野宽、瓦片碰撞自然、星露谷手感成熟 | 角色细节少 | **采纳** |
| 32×32 + 960×540 + 脚部盒 | 角色与战斗表现好、适配高分屏 | 美术量 1.5–2 倍，单人开发周期显著拉长 | 否决（可后续出新版本迁移） |
| 16×16 + 全身盒 | 实现最简 | 门/窄道卡脚，贴墙时视觉与碰撞不一致 | 否决 |
| 16×16 + 圆形盒 | 移动顺滑 | 与网格对齐差，种植/放置交互不直观 | 否决 |
| 混合尺寸（世界 16 / 角色 32） | 兼顾细节与视野 | 对齐与渲染复杂，易出现半格偏移 bug | 否决 |

## 后果

正面

- 美术成本最低，作物 3–4 阶段图与小型怪物可在数小时内完成。
- 40×22.5 格视野适合农场经营，无需频繁滚动即可看到整块田地。
- 脚部盒让门、窄道、贴墙移动手感自然，且与瓦片网格一一对应。
- 640×360 在 1080p/1440p 上均为整数倍（3×/4×），像素锐利。

负面

- 角色与武器外观辨识度低；换装内容价值不高。
- 战斗动作需要依赖特效、顿帧、屏幕震动来提升可读性（由 M20/M06 补偿）。
- 4 向精灵在纯斜向移动时视觉朝向会“锁定”到水平，需要动画师注意。

需持续关注

- 若后续决定做换装或大量武器外观，需新增 ADR 讨论迁移到 32×32 或采用分层描边方案。
- 相机若未来需要缩放，只能整数倍，且需重新评估 UI 缩放。

## 具体常量定义位置

- 编译期常量：`src/engine/render/Constants.hpp`（瓦片尺寸、虚拟分辨率）。
- 玩法可调参数：`assets/data/tuning.json`（移动速度、闪避位移、攻击范围），避免改代码。
- 碰撞盒：`Collider { glm::vec2 offsetFromFeet; glm::vec2 size; CollisionLayer layer; CollisionLayer mask; }`，`offsetFromFeet.y` 为负值向上。

## 验证方式

- Phase A 验收：1280×720（2×）与 1920×1080（3×）下精灵无模糊、无半像素抖动。
- Phase B 验收：角色可穿过 1 格宽门洞；贴墙滑动无卡顿；遮挡排序与脚底锚点一致。
- Phase D 验收：近战判定 24×20 在闪避/击退中不穿墙。
